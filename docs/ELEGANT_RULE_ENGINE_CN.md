# 精确稀疏棋盘后继

## 问题

固定棋盘上比较 64 格在复杂度上仍是常数，但它不符合一步棋的局部语义，也会让查询和回执被大量不变格等式淹没。更重要的是，两个完整数组都由宿主程序构造，逐格比较并不会自动消除可信计算边界。

## 当前表示

设走前棋盘为不可变对象 `B`，一步棋产生规范化编辑集合：

```text
E = {(index, before_piece, after_piece), ...}
```

编辑数受走法类型约束：普通着/吃子/升变为 2，吃过路兵为 3，易位为 4。编辑索引唯一，走前内容必须匹配，应用编辑后必须得到候选棋盘。

## 精确全局不变量

```text
BoardCode(B) = Σ (piece[i]+6) 16^i
```

单项贡献为：

```text
Δ_i = (after_piece-before_piece) 16^i
```

Litex 检查：

```text
BoardCode(B') = BoardCode(B) + Σ Δ_i
```

这是一种唯一数字展开，不是概率哈希；未登记的额外变化会破坏等式。

## 为什么尚未直接使用形式化有限映射

更纯粹的目标是把棋盘表示为 `Square -> Piece`，并在 Litex 中定义 `update`、外延性、路径和攻击关系。当前 beta 语言下，这会引入较重的函数更新与量化编码。现有方案在可读性、执行成本和可审计性之间取得阶段性平衡。

## 兼容层

`compact_transition.py` 可把历史逐格查询夹具转换为稀疏格式，供回归和差分审计使用。生产内核本身不再定义逐格后继谓词。
