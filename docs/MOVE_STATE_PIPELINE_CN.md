# 一手棋的状态迭代与证书链

## 1. 输入不是只有起点和终点

当前节点保存完整 `Position`：

```text
board[64], turn, castling, ep_square, halfmove, fullmove
```

因此易位权、吃过路兵机会和回合计数可以沿每条棋谱分支独立演化。

## 2. 候选构造

用户提交 `Move(from, to, promotion)` 后，`candidate.py` 机械执行可能涉及的局部操作：

- 清空源格并写入目标格；
- 吃过路兵时清除相邻兵；
- 易位时同步移动车；
- 升变时替换棋子；
- 更新轮次、易位权、ep 和回合计数。

这一阶段不证明合法性。非法 `e2e5` 也可以形成候选对象，但不能因此提交。

## 3. 证书编译

`query.py` 从走前局面重新计算：

1. 选中的棋子几何谓词；
2. 滑行路径和阻挡；
3. 规范化的 2—4 个棋盘编辑；
4. 精确全盘码增量；
5. FEN 元数据期望值；
6. 王安全和终局摘要。

查询首先写 Agent 可读封面，随后写完整证书。

## 4. 为什么不再每手比较 64 格

一步棋最多改变四格。生产表示使用：

```text
不可变走前棋盘 + canonical sparse delta
```

未列入编辑集合的格子没有写操作。精确 `BoardCode` 等式进一步排除遗漏变化。旧逐格查询只在兼容历史夹具时由 `compact_transition.py` 转换，不再属于生产规则内核。

## 5. Litex 事务与回滚

所有语句在同一 fail-closed 事务中运行。只有全部成功并到达事务哨兵，`SessionStore` 才创建新节点。失败时：

- 棋盘不变；
- FEN 不变；
- 易位权和 ep 不变；
- 候选源码与诊断仍可在工作台查看；
- 被拒绝候选不进入 PGN 树。

## 6. SAN 和结果

走后局面通过有限合法着生成器分类：

```text
checkmate / stalemate / check / ongoing
```

同一结果用于 SAN 后缀、`result(...)`、回执和教材状态实验，所以 `Qh4#` 不再与界面中的结果记录发生分叉。
